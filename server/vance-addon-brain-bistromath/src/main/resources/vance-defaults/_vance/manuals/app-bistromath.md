# Custom Applications (`app: custom`)

A **custom application** is a small program whose parts are documents. You can
create one and change what it does — with the ordinary document tools, in the
same conversation.

**Never say a new app or a change to one needs a release.** Check whether this
fits first.

The model is closer to Microsoft BASIC than to a database product: the
**program** is the middle, and reading documents is one thing it can do.

## When it fits

| Ask | Answer |
|---|---|
| "Somewhere to track invoices / equipment / applicants" | custom app |
| "A little converter / calculator" | custom app — no data at all needed |
| "Add a column to that list" | edit the view document |
| "Drag cards between columns" | Kanban — the interaction *is* the product |
| "Write me a page of notes" | a workpage, not an app |

## The three documents

```
apps/invoices/
  _app.yaml        the manifest — usually just a title
  main.yaml        a view: $meta.kind: app-view + a widget tree
  main.js          the program
  _index.md        generated by app_rebuild: what the runtime found
```

**No prescribed folders.** A view is a view because its header says so, so it
can sit anywhere under the app folder. Data can live in any folder you like —
the program names the path.

## Creating one

```
bistromath_app_create(folder="apps/invoices", title="Invoice register")
```

Scaffolds a working Hello World: a button, a text line, and a program that
answers. Do not hand-write `_app.yaml` — the tool owns its format.

## The one rule for data

> A widget shows **state**. The **program** writes state. The program reads
> documents through `vance.*`.

There is no table declaration anywhere, and no `source:` on a widget. A folder
of documents is a fine way to store records — one document per row, file name
as the key — but that is a habit, not something the runtime knows about.

```js
async function init() {
  const files = await vance.documents.list('invoices/');
  const rows = [];
  for (const f of files) {
    rows.push({ key: f.key, ...(await vance.documents.read(f.path)) });
  }
  vance.state.set('invoices', rows);
}
```

```yaml
  - type: table
    from: invoices          # the state key init() filled
    columns: [nr, customer, amount]
```

## The program

`main.js` in the app folder. Plain top-level functions — no `export`.

| Function | When |
|---|---|
| `init()` | once, when the app opens |
| `shutdown()` | when it closes — **not guaranteed**, never the only place you save |
| anything else | called by a handler in a view |

It is **one long-running program**, not one call per click: a variable at the
top of the file keeps its value between clicks. It stops when the app closes;
nothing survives to the next opening except what you wrote into documents.

The sandbox has no DOM, no cookies, no `fetch`. Only `vance.*`:

| Call | Does |
|---|---|
| `vance.state.set(key, value)` | what widgets show |
| `vance.documents.list(path)` | documents directly in a folder → `{key, path, title, mime}` |
| `vance.documents.read(path)` | content; parsed to an object for YAML/JSON |
| `vance.ui.notify(text)` | a message above the page |
| `vance.ui.show(handle)` | switch to another view |

A path is relative to the app folder; a leading `/` means the project root.

## The view

```yaml
$meta:
  kind: app-view
type: page
title: Invoices
children:
  - type: toolbar
    children:
      - type: button
        label: Reload
        on: { click: "main.js:load" }
  - type: table
    from: invoices
    on: { rowClick: "navigate:detail" }
```

Widgets: `page`, `toolbar`, `button`, `text`, `markdown`, `table`, `form`,
`tabs`. A view's handle is its **file name** (`detail.yaml` → `detail`), which
is also what a deep link points at.

Handlers are one string: `reload`, `navigate:<handle>`, or
`<program>:<function>`. The separator is `:` — **not** `#`, which would be
discarded as a URI fragment. A `rowClick` that navigates carries the clicked
row's `key`, so a detail view can show that record with `from:` on a `form`.

**After editing anything, run `app_rebuild(folder="apps/invoices")`.** It
re-reads every view, reports what does not parse, and rewrites `_index.md` with
what the runtime actually found — nothing else validates a view.

## What this build does not do

- **No writing.** `vance.documents.write` does not exist yet: the conflict
  policy is unsettled, and a naive write loses somebody's edit. Apps read.
- **No `visibleIf`.** A conditional field is refused rather than shown
  unconditionally.
- **`if`, `repeat`, `chart`, `dialog`** are reserved, not rendered.
- **No imports** in the program — one file, evaluated as one script.
- **No cross-project paths.**

## Errors worth recognising

| Message | Cause |
|---|---|
| `unknown widget` | typo in `type:` |
| `is part of the schema but is not rendered yet` | a reserved widget |
| `` `source` no longer exists `` | use `from:` and have the program fill the key |
| `a table needs from` | name the state key |
| `not evaluated yet` | remove `visibleIf` |
| `no function named X` | the handler names a function `main.js` does not define |
| `The program stopped responding` | an endless loop; the frame was stopped |
| `carries showIf` | that is the setting-form condition, not read here |
